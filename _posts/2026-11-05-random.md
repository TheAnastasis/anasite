## Math
During earlier Rank 1 routing attempts, I found something very interesting: sometimes, it took 11 goal points to rank up.

For the uninitiated, goal points are the internal points system (exposed in UI elements in Revamped and further expanded upon in AnaMod). Gaps give 1, Secret Spots give 5, and different goal types give anything 10, 20, or 30.

The game *actually* doesn't have a fixed number of goal points per rank. The game, instead, uses a formula similar to this:
`rank = 200 - ceil(goal_points / 1470 * 146)`

On average, a rank equates to ~10.07 on average. Points and ranks are whole numbers, not floats, but the game does consider it for later. Every 14 to 15 ranks, the game will require 11 goal points to rank up instead 0of 10.

Over the course of the game, that means there are 9 ranks that cost 11: 184, 169, 155, 140, 126, 111, 96, 82, and.... 67.

The final requirements are as follows:
-   Rank 8 Goal: 1470 goal points + 4 pro challenges completed
-   Rank 4 Goal: 1800 goal points + 7 pro challenges completed + > 79% PRO/SICK goals
-   Rank 1 Goal: 2150 goal points + all pro challenges completed + > 95% SICK goals

Here are some additional fun stats:
-   Goals: 1,910 total (over 155 goals)
-   Gaps: 283 total (over 283 gaps)
-   Secret Spots: 180 (over 36 tokens)
-   Overall Total: 2,373


## Fast Rodney
In late-2025, pug discovered a glitch with Rodney where, if you mash the L3 + R3 buttons (Nail the Trick) after you complete a checkpoint, it would force move more checkpoints at once. If you time it right, you skip to the very end of the goal! Too fast, the game crashes!

Only issue? It was a 360-exclusive glitch. Within the Tony Hawk community, there are very, very few instances of version-exclusive glitches.

When I began AnaMod, one thing I did was look into what caused it. Based on everything I knew at the time, I knew ithad to be a script change somewhere. So, I went digging.

I found a single difference between the QB scripts related to Rodney's goal on 360 and PS3: `KillSpawnedScript \{ name = m_pro_mullen_CheckFlagAndBeatGoal }`

Remove it? And the trick is restored on PS3!

With Nail the Tricks, the game signals that you "landed" even if you are in the air upon finishing the trick - even if nothing happened. By mashing, the game is seeing multiple "landed" states, which in turn spawns an instance of `m_pro_mullen_CheckFlagAndBeatGoal`. Each instance then sees if the current checkpoint/lesson is done, and if it should proceed; and, if so, it spawns `GMan_PassCheckPoint`.

`GMan_PassCheckPoint` literally just says "skip to next checkpoint" without checking the current state. And, on 360, it stacks.

`KillSpawnedScript` does as the name implies, and is is the proper way to prevent abuse. By the time it gets to that line in the sequence, it is off to the next checkpoint and all other instances are killed.

Assumingly (I haven't tested a lot), the game crashes because you have more `GMan_PassCheckPoints` spawned then what is allowed (and they persist through cutscenes), so the game freaks out and just crashes.

## Suburbia's Exit Crash
There has been a crash that has plagued speedrunners (mostly me) for the last 10 years - in very rare scenarios, the game will crash upon finishing the `Outo f suburbia~ goal to unlock Main Street. Just like with Fast Rodney, I decided to look into the code and see what was going on. Luckily, it was an oversight in the code and not an issue with the executable.

Looking into the code, I found nothing really noticeable at first. But, seeing as it was early on in my learning of the scripting language, I decided to do some tests.

I rigged the game to try different things. Was it a slow-mo thing? Was it a freak accident? Was it a streaming/asset issue?

Tried them all and nothing.

Then, it dawned on me there is one variable I never checked: respawning.

When you wallplant the breaker to unlock it, you force a bail immediately to skip the slow-mo and begin the cutscene to unlock Main Street. There is a weird quirk with bails that I have noted over the years, and it is related to a quick "get-up" animation - sometimes even in the air.

Other times, the game may put you in a much different spot (think of it as a "most safe" location) for the bail. So.... What if the bail animation into quick get-up threw me in a weird spot?

Tested it. Crashed!

Delving into it deeper, I discovered it was an issue to do with the boundaries of the goal and the out-of-bounds portion of the goal itself.

When you cross the boundary, it starts `m_unlock_houses_StartAreaLeaving` which calls a warning timer which then calls `GMan_ResetTimer` (the countdown you are given to return to the main area). The issue is that you must call - usually in checkpoints - if you are going to use a boundary and specify the warning timer.

When this timer starts, and if you are in the Suburbia exit cutscenes, the game will check to see if it has the correct "tools" (in this case the warning timer) assigned. The cutscenes do not (since they are not boundaries), reads from null, and crashes with an access violation.

Some code was added here to ensure it doesn't happen again. Additional checks show that other goals (Unlock Slums, Rodney's Pro Challenge, Stevie & Dustin's Pro Challenge, and a few others) suffer from the same bug, but are much harder to impossible to pull off in normal gameplay. Those specific instances were *not* fixed, but if they are ever a problem then I know what to patch!

## CAREER and SPEEDRUN Modes
I toyed with this idea a good bit, but ultimately decided on my current model for the story mode: a new menu that lets you toggle between Career/Story and Speedrun modes.

I looked heavily into whether it would be possible to have a combined "save" for Career and Speedrunning, and have each have their own state. However, after a lot of testing and research, I determined it wouldn't be possible.

The game has enough room in its flag system (1024 max, which ~30% are used?), and the story mode honestly rarely uses them. Unless it is unlocking an area, remembering you unlocked skaters, or the like, the game doesn't use them as often as you would think.

Instead, the game stores a LOT of data in what are called Atoms. Now, admittedly, I haven't delved into it a lot, but Atoms is essentially the goals system and how it handles progression and so on. Without deep patching, this area cannot be saved - reading is fine and used a lot, but writing back to Atoms is outside what the programming language can do.

Now, Atoms can be interacted with - sort of - if the Debug option is checked, but all this doesis is trigger pre-made scripts by the developers to do a specific function. I can't just lift this, since this is baked into the game and are not scripts.

Instead, in the end, I decided on combining the modes, giving the player a warning upon switching modes (e.g. you keep some things for Career, but Speedrun mode wipes you clean except for achievements), and just doing it that way. There are functions to reset the career mode, so that is used to wipe the Atoms clean and restart progression, with some quality-of-life changes added so players can keep their skaters and decks.
